# 1C:Enterprise — Справочник API БСП

## Описание

Офлайн-справочник по программному интерфейсу Библиотеки стандартных подсистем (БСП) 1С: 2624 метода в 284 модулях, 71 подсистема, версии 3.1.11 и 3.2.1. Позволяет проверить вызов метода БСП перед написанием кода. **НЕ** для API самой платформы (см. 1c-platform-docs) и **НЕ** для прикладных конфигураций (ERP, ЗУП, БП).

## Когда использовать

- Пишешь код на конфигурации с БСП и нужно узнать имя модуля или метода
- Нужна сигнатура метода, его контекст выполнения (сервер/клиент)
- Нужно проверить существование метода перед вызовом (БСП-имена длинные, выдумка выглядит как оригинал)
- Нужно найти переопределяемый обработчик под задачу
- Нужно найти нужный общемодульный метод по описанию задачи

## Инструкции

### Главное правило

**Не пиши вызов метода БСП, не проверив его.** Классические несуществующие:
- `ФайловаяСистемаКлиентСервер`
- `JSONСтрокой`
- `Пользователи.СсылкаТекущегоПользователя`

### Суффиксы модулей = контекст выполнения

| Суффикс | Где исполняется | Пример |
|---------|----------------|--------|
| без суффикса или `Сервер` | сервер, толстый клиент, внешнее соединение | `ОбщегоНазначения` |
| `Клиент` | тонкий и толстый клиент | `ОбщегоНазначенияКлиент` |
| `КлиентСервер` | и там, и там | `ОбщегоНазначенияКлиентСервер` |
| `ВызовСервера` | сервер, вызывается с клиента напрямую | `ОбщегоНазначенияВызовСервера` |

**Частая ошибка:** серверный метод вызывают из клиентского кода. Контекст каждого метода есть в справочнике.

### Поиск по описанию

```
bsp-api("фоновое задание прогресс")  → ОбщегоНазначения.ФоновоеЗаданиеВыполнено
bsp-api("копирование структуры")     → ОбщегоНазначения.СкопироватьРекурсивно
```

### Проверка существования вызова

```
bsp-api("check ОбщегоНазначенияКлиент.ПараметрыРаботыКлиента")
```

Если вызов не найден, инструмент подсказывает похожие имена — и по модулю, и по методу.

### Типичный workflow

1. **Найти метод** — `bsp-api("описание задачи")` — найти подходящий модуль/метод
2. **Проверить сигнатуру** — `bsp-api("show Модуль.Метод")` — получить параметры и контекст
3. **Вызвать в коде** — использовать найденный метод с правильным контекстом

### Разделение по контекстам

Вызов серверного метода из клиентского кода — ошибка. Проверяй суффикс модуля:

| Суффикс | Сервер | Тонкий клиент | Толстый клиент | Внешнее соединение | Вызов сервера |
|---------|:------:|:-------------:|:--------------:|:-------------------:|:-------------:|
| `Сервер` / без суффикса | ✓ | ✗ | ✓ | ✓ | ✗ |
| `Клиент` | ✗ | ✓ | ✓ | ✗ | ✗ |
| `КлиентСервер` | ✓ | ✓ | ✓ | ✓ | ✗ |
| `ВызовСервера` | ✓ | ✗ | ✗ | ✗ | ✓ |

## Примеры

```bsl
// Правильно: серверный метод на сервере
Результат = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Ссылка, "Наименование");

// Ошибка: вызов КлиентСервер модуля из серверного кода — проверь контекст!
// ОбщегоНазначенияКлиент.ПараметрыРаботыКлиента() — только с клиента

// Правильно: Клиент вызов с клиента
Параметры = ОбщегоНазначенияКлиент.ПараметрыРаботыКлиента();
```

## Лучшие практики

- **Всегда проверяй вызов** — БСП-имена правдоподобно выдумываются
- **Проверяй контекст** — суффикс модуля определяет, где можно вызывать
- **Используй общие модули БСП** вместо дублирования кода
- **Не называй свои модули как модули БСП** — это путает
