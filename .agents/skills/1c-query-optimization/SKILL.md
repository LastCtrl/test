# 1C:Enterprise — Продвинутая оптимизация запросов

## Описание

Продвинутые паттерны оптимизации запросов 1С: временные таблицы вместо подзапросов, оптимизация JOIN, оптимизация СКД-отчётов, обработка больших объёмов данных порциями. Дополняет базовые правила из 1c-query.

## Когда использовать

- Сложные запросы с многошаговой обработкой данных
- Оптимизация JOIN и подзапросов
- Реализация отчётов СКД (ДополнительныеИсточникиДанных)
- Обработка больших выборок порциями
- Поиск узких мест в производительности запросов

## Инструкции

### 1. JOIN vs подзапрос — базовый выбор

```bsl
// ПРЕДПОЧТИТЕЛЬНО: JOIN (обычно быстрее)
"ВЫБРАТЬ
|	Заказы.Ссылка КАК Заказ,
|	Контрагенты.ИНН КАК ИНН
|ИЗ
|	Документ.ЗаказКлиента КАК Заказы
|		ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Контрагенты
|		ПО Заказы.Контрагент = Контрагенты.Ссылка"

// ИЗБЕГАТЬ: Подзапрос в SELECT (проблема N+1)
"ВЫБРАТЬ
|	Заказы.Ссылка КАК Заказ,
|	(ВЫБРАТЬ К.ИНН ИЗ Справочник.Контрагенты КАК К
|	 ГДЕ К.Ссылка = Заказы.Контрагент) КАК ИНН
|ИЗ
|	Документ.ЗаказКлиента КАК Заказы"
```

### 2. Избегай агрегации в подзапросах

```bsl
// ПЛОХО: Агрегация в подзапросе
"ВЫБРАТЬ
|	Док.Ссылка,
|	(ВЫБРАТЬ СУММА(Т.Сумма) ИЗ Документ.Заказ.Товары КАК Т
|	 ГДЕ Т.Ссылка = Док.Ссылка) КАК Итого
|ИЗ Документ.Заказ КАК Док"

// ХОРОШО: JOIN + группировка
"ВЫБРАТЬ
|	Док.Ссылка,
|	СУММА(Т.Сумма) КАК Итого
|ИЗ Документ.Заказ КАК Док
|	ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.Заказ.Товары КАК Т
|	ПО Т.Ссылка = Док.Ссылка
|СГРУППИРОВАТЬ ПО Док.Ссылка"
```

### 3. Временные таблицы для многошаговой обработки

```bsl
// Шаг 1: Собрать данные во ВТ
"ВЫБРАТЬ Ссылка КАК Док
|ПОМЕСТИТЬ ВТ_Документы
|ИЗ Документ.Реализация
|ГДЕ Дата МЕЖДУ &Начало И &Конец
|ИНДЕКСИРОВАТЬ ПО Док
|;
// Шаг 2: Использовать ВТ для отбора
|ВЫБРАТЬ
|	Док.Ссылка,
|	СУММА(Т.Сумма) КАК Сумма
|ИЗ ВТ_Документы КАК Док
|	ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.Реализация.Товары КАК Т
|	ПО Т.Ссылка = Док.Ссылка
|СГРУППИРОВАТЬ ПО Док.Ссылка"
```

### 4. Обработка больших выборок порциями

```bsl
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1000 Ссылка ИЗ Справочник.Номенклатура ГДЕ НЕ ПометкаУдаления";

МассивСсылок = Новый Массив;
Выборка = Запрос.Выполнить().Выбрать();
Пока Выборка.Следующий() Цикл
    МассивСсылок.Добавить(Выборка.Ссылка);
    Если МассивСсылок.Количество() >= 1000 Тогда
        // Обработать порцию
        ОбработатьПорцию(МассивСсылок);
        МассивСсылок.Очистить();
    КонецЕсли;
КонецЦикла;
// Обработать остаток
Если МассивСсылок.Количество() > 0 Тогда
    ОбработатьПорцию(МассивСсылок);
КонецЕсли;
```

### 5. Оптимизация СКД

- Используй `ВнешниеИсточникиДанных` вместо запроса в обработчике расчёта
- Фильтруй на уровне СКД, а не в коде
- Используй предварительные отборы (`ПредставленияПолей`, `Отбор`)

## Лучшие практики

- **JOIN > подзапрос** — в большинстве случаев быстрее
- **ВТ вместо вложенных подзапросов** — улучшает читаемость и производительность
- **Индексируй ВТ** — если строк >1000 и используется в JOIN/В
- **Не создавай ВТ в цикле** — O(N²)
- **Используй ПЕРВЫЕ** вместо загрузки всего объёма
- **Проверяй план запроса** — через `EXPLAIN` или профайлер
