# Evidence-Discipline (анти-галлюцинации)

Обязателен для ВСЕХ агентов. Цель — не допускать выдуманных файлов, команд, API и ложных «готово».

## 6 правил (нарушение = REJECT)

1. **Не утверждай существование без проверки.** Прежде чем сказать «файл X есть», «команда Y работает», «API Z возвращает» — прочитай файл (Read) или выполни команду. Нет проверки → не утверждай.
2. **Не проверено → явно пиши `NOT ENOUGH EVIDENCE: <что именно>`.** Не догадывайся и не заполняй пробелы фантазией.
3. **`DONE` только с артефактом.** Артефакт = путь к файлу + подтверждение (вывод команды, строка файла, diff). Нет артефакта → статус `PARTIAL`.
4. **Ссылки на код — только `path:line` после чтения.** Не выдумывай номера строк и имена функций.
5. **Отсутствующее — называй `missing`.** Скилл/скрипт/модель/файл, которых нет, — так и пиши: `missing`. Не подменяй похожим.
6. **Различай три состояния:** «прочитал/проверил» · «предполагаю» · «сделал». В отчёте они не смешиваются.

## В self-report (обязательно)

- `SKILLS_LOADED` и `MCP_USED` — только реально использованные; пусто → так и писать (`[]` или `["<name>: offline"]`).
- Для каждой заявленной правки — путь + краткое доказательство.
- Если что-то не проверено — строка `NOT ENOUGH EVIDENCE: ...`.

## Триггеры доп. проверки

- Утверждение «готово/работает/исправлено» → обязателен артефакт.
- Ссылка на внешнюю библиотеку/фреймворк → сверить через context7 (иначе `NOT ENOUGH EVIDENCE`).
- Задача > 3 шагов → sequential-thinking.

## Анти-примеры (нельзя)

- «Создал файл config.yaml» — когда файл не создавался/не проверен.
- «Тесты прошли» — без вывода тестов.
- «Модель X лучше» — без метрики и sample_count.
- «Скилл Y загружен» — когда его нет в `.agents/skills/`.
