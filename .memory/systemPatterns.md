# System Patterns — Наблюдаемые паттерны

## Паттерн 1: Fallback-стратегия (LLM → simple list)
- **Где**: news-bot/services/analyzer.py
- **Суть**: Если LLM недоступен/вернул пустоту → используется _format_simple_list (заголовки без AI)
- **Причина**: opencode API не публичный, ключи-заглушки, модели работают через CLI
- **Решение**: LLM-слой удалён из analyzer.py для простых запросов

## Паттерн 2: Протокол отката (2 попытки → другой агент)
- **Где**: все агенты
- **Суть**: Максимум 2 попытки на задачу → откат изменений → передача агенту с более сильной моделью
- **Иерархия**: mimo-v2.5-pro → kimi-k2.7-code → deepseek-v4-pro → qwen3.7-plus → glm-5.2
- **Причина**: Предотвращение бесконечного копания в одной проблеме

## Паттерн 3: Параллельное делегирование
- **Где**: team-lead → backend + devops
- **Суть**: Независимые задачи запускаются в одном сообщении (task tool)
- **Пример**: Поиск бага (backend) + диагностика Redis (devops) параллельно

## Паттерн 4: .bak-копии перед правками (когда нет git)
- **Где**: D:\ЛичныйКабинет\lk_fl-main (не git-репозиторий)
- **Суть**: Перед каждым изменением файла — создаётся .bak копия
- **Откат**: Восстановление из .bak вместо git checkout
- **Причина**: Проект без системы контроля версий

## Паттерн 5: py_compile проверка после каждого изменения Python
- **Где**: все Python-задачи
- **Суть**: После каждого изменения .py файла — py_compile для проверки синтаксиса
- **Причина**: Быстрый поиск опечаток и синтаксических ошибок

## Паттерн 6: Защита от двойного клика
- **Где**: news-bot (handlers/search.py, services/scheduler.py)
- **Суть**: In-memory флаги (_pending_digests, _pending_more) + callback.answer("⏳ Загружаю...")
- **Причина**: Пользователи жмут кнопки несколько раз → дублирование запросов

## Паттерн 7: Предзагрузка кэша (TTL + create_task)
- **Где**: news-bot (services/tts.py, services/scheduler.py)
- **Суть**: Предзагрузка за 3 минуты до использования через asyncio.create_task
- **Причина**: TTS-генерация занимает время → показать результат мгновенно

## Паттерн 8: Миграция без потери данных
- **Где**: news-bot/database.py
- **Суть**: PostgreSQL-style ALTER TABLE через sqlite3 + if not exists
- **Причина**: SQLite не поддерживает ALTER TYPE → ручная миграция

## Паттерн 9: Контрольный прогон после фикса
- **Где**: все задачи
- **Суть**: После фикса — полный цикл send-code → verify-code = 200
- **Причина**: Убедиться что фикс реально работает, а не только компилируется
