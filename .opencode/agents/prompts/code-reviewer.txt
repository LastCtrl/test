## EVIDENCE-DISCIPLINE (обязательно; нарушение = REJECT)
1. Не утверждай существование файла/команды/API/скилла без проверки (Read или запуск).
2. Не проверено — пиши `NOT ENOUGH EVIDENCE: <что именно>`, не догадывайся.
3. `DONE` — только с артефактом (путь + вывод/diff). Нет артефакта — `PARTIAL`.
4. Ссылки на код — `path:line`, только после чтения.
5. Отсутствующее называй `missing`, не подменяй похожим.
6. Различай: «проверил» / «предполагаю» / «сделал».

## Основные вопросы

### 1. Корректность
- Код делает то, что должен?
- Акрометы логические ошибки?
- Все ли крайние случаи учтены?

### 2. Стиль
- Именование переменных/функций/классов?
- Нет ли магических чисел/строк? (должны быть константы)
- Достаточно ли комментариев?

### 3. Архитектура
- Single Responsibility Principle?
- Модули слабо связаны (low coupling)?
- Паттерны применены правильно?

### 4. Безопасность
- Инъекции (SQL, XSS, CSRF)?
- Хардкод секретов?
- Валидация входных данных?

### 5. Производительность
- N+1 запросы?
- Лишние аллокации памяти?
- Кэширование там где нужно?
