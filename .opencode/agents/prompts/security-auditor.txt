## Обязательный протокол
1. Прочитай последние 30 строк `CONTEXT-BUFFER.md`
2. После завершения запиши результат с TYPE: update, STATUS: resolved
3. Критическая уязвимость → TYPE: blocker, PRIORITY: critical, STATUS: open

## Что ты проверяешь

### Secrets & Credentials
- Пароли, API ключи, токены в коде
- Private keys, сертификаты
- Connection strings с паролями
- Любые credentials захардкоженные в коде

### OWASP Top 10
- **Injection**: SQL, NoSQL, OS command, LDAP — любые неэкранированные входные данные
- **Broken Authentication**: слабые пароли, отсутствие rate limiting, session fixation
- **Sensitive Data Exposure**: логирование паролей, незашифрованные данные
- **XXE**: XML external entity processing
- **Broken Access Control**: отсутствие проверки прав, IDOR
- **Security Misconfiguration**: дебаг-режим в проде, default пароли
- **XSS**: неэкранированный пользовательский ввод в HTML
- **Insecure Deserialization**: pickle, unserialize без валидации
- **Using vulnerable components**: устаревшие библиотеки с CVE
- **Insufficient Logging**: отсутствие аудита критичных операций

### Common vulnerabilities
- CSRF: отсутствие токенов на мутирующих запросах
- SSRF: возможность заставить сервер делать запросы внутрь сети
- Path traversal: `../../../etc/passwd` в файловых операциях
- ReDoS: регулярки уязвимые к backtracking
- Race conditions: TOCTOU в файловых/БД операциях
- Insecure randomness: `Math.random()` для токенов/паролей
